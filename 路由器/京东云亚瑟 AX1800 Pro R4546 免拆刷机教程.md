# 京东云亚瑟 AX1800 Pro R4546 免拆刷机教程

## 一、适用范围

本教程适用于：

- 设备：京东云无线宝亚瑟 AX1800 Pro
- 设备代号：`JDCloud RE-SS-01`
- 原厂固件：`4.5.3.r4546`
- 存储：64GB 或128GB eMMC
- 目标系统：iStoreOS/OpenWrt
- 操作方式：不拆机，通过原厂后台漏洞开启 Telnet

R4546 的新免拆方法是在登录原厂后台后，通过浏览器控制台调用内部接口启动 Telnet，不需要先降级，也不需要绑定京东 App。该方法由2026年6月发布的社区教程验证。

> **重要提醒**
>
> 刷写 U-Boot 存在变砖风险。必须先完成备份并把备份下载到电脑，才能继续刷写。
>
> 亚瑟必须使用 `jdcloud_re-ss-01` 文件，不能使用雅典娜的 `jdcloud_re-cs-02`，也不能使用太乙的 `jdcloud_re-cs-07`。OpenWrt 主线代码已经确认亚瑟对应型号为 RE-SS-01。

# 二、刷机总体流程

```text
确认型号和R4546版本
        ↓
断开WAN，电脑连接LAN口
        ↓
登录192.168.68.1
        ↓
F12控制台开启Telnet
        ↓
Telnet登录原厂系统
        ↓
检查分区表和设备型号
        ↓
备份GPT、p1～p25和ART
        ↓
把备份下载到电脑并校验
        ↓
下载亚瑟专用U-Boot并校验
        ↓
写入APPSBL A/B两个槽位
        ↓
回读校验U-Boot
        ↓
按住RESET进入U-Boot网页
        ↓
刷默认分区版iStoreOS Factory
        ↓
进入iStoreOS并修改密码
```

本教程不在第一次刷机时修改 GPT 分区表。这样可以避免同时操作 U-Boot、GPT 和系统固件，降低刷砖风险。

# 四、刷机前网络设置

## 4.1 物理连接

连接方式：

```text
电脑网口 ───── 网线 ───── 亚瑟LAN口
```

注意：

- 使用三个黑色 LAN 口中的任意一个；
- 暂时不要连接蓝色 WAN 口；
- 电脑关闭 Wi-Fi；
- 暂时关闭 VPN、Clash、V2Ray和系统代理；
- 只保留电脑与亚瑟之间的本地连接。

断开 WAN 可以避免刷机过程中系统自动升级，也能避免开启的 Telnet 端口暴露到外网。

## 4.2 登录原厂后台

浏览器访问：

```text
http://192.168.68.1
```

登录管理后台。

记住后台管理密码，稍后 Telnet 登录时：

```text
用户名：root
密码：原厂后台管理密码
```

R4546 的 Telnet 登录密码与 Web 后台管理密码相同。

# 五、在 R4546 上开启 Telnet

## 5.1 打开浏览器控制台

登录路由器后台后：

1. 按 `F12`；
2. 切换到 `Console`，即“控制台”；
3. 清空控制台中的旧内容；
4. 粘贴下面的完整脚本；
5. 按回车执行。

部分浏览器可能阻止直接粘贴。若控制台提示需要允许粘贴，按照控制台提示输入允许粘贴的文字，再重新粘贴脚本。

## 5.2 执行 R4546 Telnet 脚本

```javascript
(async () => {
    const session = document.cookie
        .split('; ')
        .find(r => r.startsWith('sessionid='))
        ?.split('=')[1];

    if (!session) {
        console.error('未获取到sessionid，请确认已经登录路由器后台');
        return;
    }

    const exec = async (cmd) => {
        const response = await fetch('/jdcapi', {
            method: 'POST',
            headers: {
                'Content-Type': 'application/json'
            },
            body: JSON.stringify({
                jsonrpc: '2.0',
                id: 1,
                method: 'call',
                params: [
                    session,
                    'jdcapi.static',
                    'set_port_forward',
                    {
                        'on-off': 1,
                        name: 't1',
                        proto: 'TCP',
                        'src-dport': `1234;\`${cmd}\``,
                        ipaddr: '192.168.1.100',
                        'dest-port': '80',
                        edit: 1
                    }
                ]
            })
        });

        if (!response.ok) {
            throw new Error(`HTTP错误：${response.status}`);
        }
    };

    try {
        await exec('factory_hm info telnet 1');
        await exec('telnetd');
        console.log(
            'Telnet已开启：地址为路由器后台IP，用户名root，密码为后台管理密码'
        );
    } catch (error) {
        console.error('开启Telnet失败：', error);
    }
})();
```

该脚本来自 R4546 免拆刷机社区方案，通过 `jdcapi.static/set_port_forward` 参数注入执行 `factory_hm info telnet 1` 和 `telnetd`。

## 5.3 测试23端口

在 Windows PowerShell 中执行：

```powershell
Test-NetConnection 192.168.68.1 -Port 23
```

正常情况下应显示：

```text
TcpTestSucceeded : True
```

如果为 `False`：

- 确认仍然登录在路由器后台；
- 刷新后台并重新执行脚本；
- 确认脚本没有红色错误；
- 不要关闭后台页面后再执行；
- 确认电脑仍获得 `192.168.68.x` 地址。

# 七、检查设备型号和分区

依次执行：

```sh
uname -a
cat /etc/openwrt_release 2>/dev/null
cat /proc/cpuinfo | head -30
fdisk -l /dev/mmcblk0
df -h
blkid
```

检查是否存在以下分区：

```sh
ls -l /dev/mmcblk0p13
ls -l /dev/mmcblk0p14
ls -l /dev/mmcblk0p15
```

解析 APPSBL 分区：

```sh
APPSBL_A="$(blkid -t PARTLABEL=0:APPSBL -o device)"
APPSBL_B="$(blkid -t PARTLABEL=0:APPSBL_1 -o device)"

echo "APPSBL_A=$APPSBL_A"
echo "APPSBL_B=$APPSBL_B"
```

正常情况下应得到：

```text
APPSBL_A=/dev/mmcblk0p13
APPSBL_B=/dev/mmcblk0p14
```

如果输出为空、分区编号不同，或者没有 `mmcblk0p15`：

> **立即停止，不要刷 U-Boot。**

亚瑟原厂分区通常将两个 APPSBL/U-Boot 槽位放在 p13、p14，ART 无线校准分区为 p15。ART 包含每台设备独有的 MAC、序列号和无线射频校准数据。

# 八、完整备份原厂关键数据

## 8.1 检查存储分区空间

先执行：

```sh
df -h | grep -E 'mmcblk0p27|storage|plugin'
mount | grep mmcblk0p27
```

假设 p27 已经挂载到：

```text
/mnt/mmcblk0p27
```

检查可用空间：

```sh
df -h /mnt/mmcblk0p27
```

建议至少保留2GB可用空间。

如果 p27 没有挂载，或者空间不足，应改用 U盘。先执行：

```sh
lsblk
mount
```

根据实际挂载位置修改后面的 `BACKUP_ROOT`。

## 8.2 创建备份目录

使用 p27 时执行：

```sh
BACKUP_ROOT=/mnt/mmcblk0p27
BACKUP_DIR=$BACKUP_ROOT/ax1800_r4546_backup

mkdir -p "$BACKUP_DIR"
cd "$BACKUP_DIR"
pwd
```

确认输出目录正确后继续。

## 8.3 保存设备信息

```sh
date > device_info.txt
uname -a >> device_info.txt
cat /etc/openwrt_release >> device_info.txt 2>/dev/null
fdisk -l /dev/mmcblk0 >> device_info.txt
blkid >> device_info.txt
mount >> device_info.txt
df -h >> device_info.txt
```

## 8.4 逐个备份 p1～p25

```sh
for i in $(seq 1 25); do
    echo "正在备份 mmcblk0p$i"
    dd if="/dev/mmcblk0p$i" \
       of="$BACKUP_DIR/mmcblk0p$i.bin" \
       bs=1M
    sync
done
```

不要漏掉：

```text
mmcblk0p13.bin    原厂U-Boot槽位A
mmcblk0p14.bin    原厂U-Boot槽位B
mmcblk0p15.bin    ART无线校准数据
```

## 8.5 备份 GPT

```sh
dd if=/dev/mmcblk0 \
   of="$BACKUP_DIR/gpt_primary.bin" \
   bs=512 count=34

TOTAL_SECTORS=$(blockdev --getsz /dev/mmcblk0)

dd if=/dev/mmcblk0 \
   of="$BACKUP_DIR/gpt_backup.bin" \
   bs=512 skip=$((TOTAL_SECTORS - 33)) count=33

sync
```

## 8.6 可选：备份 eMMC 前1111MB

如果空间足够，建议额外执行：

```sh
dd if=/dev/mmcblk0 \
   of="$BACKUP_ROOT/ax1800_first_1111m.img" \
   bs=1M count=1111

sync
```

社区救砖教程通常使用该镜像保留前部引导、分区表和原厂关键分区。

## 8.7 生成校验文件

```sh
cd "$BACKUP_DIR"

md5sum *.bin > md5sums.txt
sha256sum *.bin > sha256sums.txt

ls -lh
du -sh .
```

检查关键文件不能是0字节：

```sh
ls -lh \
    mmcblk0p13.bin \
    mmcblk0p14.bin \
    mmcblk0p15.bin \
    gpt_primary.bin \
    gpt_backup.bin
```

## 8.8 打包备份

```sh
cd "$BACKUP_ROOT"

tar -cf ax1800_r4546_backup.tar ax1800_r4546_backup

sync
ls -lh ax1800_r4546_backup.tar
```

## 8.9 将备份下载到电脑

在路由器中启动临时 HTTP 服务：

```sh
busybox httpd -p 8080 -h "$BACKUP_ROOT"
```

电脑浏览器打开：

```text
http://192.168.68.1:8080/
```

下载：

```text
ax1800_r4546_backup.tar
ax1800_first_1111m.img
```

将文件保存到：

```text
D:\AX1800Pro\03_Backup\
```

备份下载完成后，在电脑上至少保留两份：

- 电脑硬盘一份；
- U盘、移动硬盘或网盘一份。

备份完成后，关闭临时 HTTP 服务：

```sh
killall httpd
```

# 十一、刷写前的最后安全检查

设置变量：

```sh
cd /tmp

UBOOT=/tmp/uboot-ipq60xx-emmc-jdcloud_re-ss-01.bin

APPSBL_A="$(blkid -t PARTLABEL=0:APPSBL -o device)"
APPSBL_B="$(blkid -t PARTLABEL=0:APPSBL_1 -o device)"

echo "UBOOT=$UBOOT"
echo "APPSBL_A=$APPSBL_A"
echo "APPSBL_B=$APPSBL_B"
```

必须显示：

```text
APPSBL_A=/dev/mmcblk0p13
APPSBL_B=/dev/mmcblk0p14
```

检查文件和分区大小：

```sh
FILE_SIZE=$(wc -c < "$UBOOT")
A_SIZE=$(blockdev --getsize64 "$APPSBL_A")
B_SIZE=$(blockdev --getsize64 "$APPSBL_B")

echo "U-Boot文件大小：$FILE_SIZE"
echo "A槽分区大小：$A_SIZE"
echo "B槽分区大小：$B_SIZE"
```

执行自动判断：

```sh
if [ "$FILE_SIZE" -gt "$A_SIZE" ] || \
   [ "$FILE_SIZE" -gt "$B_SIZE" ]; then
    echo "错误：U-Boot文件大于APPSBL分区，禁止刷写"
else
    echo "文件大小检查通过"
fi
```

只有显示：

```text
文件大小检查通过
```

才能继续。

# 十二、写入亚瑟专用 U-Boot

## 12.1 写入 A 槽

```sh
dd if="$UBOOT" of="$APPSBL_A" bs=128K
sync
```

## 12.2 写入 B 槽

```sh
dd if="$UBOOT" of="$APPSBL_B" bs=128K
sync
```

社区教程均采用将第三方 U-Boot 写入 APPSBL A/B两个槽位的方式，通常对应 p13和p14。

> 不要执行清空 BOOTCONFIG 的命令。
>
> 不要修改 p1、p2、p3、p10、p11或p15。
>
> 不要在写完后立即拔电。

---

# 十三、回读校验 U-Boot

先获取源文件 MD5和长度：

```sh
FILE_SIZE=$(wc -c < "$UBOOT")
md5sum "$UBOOT"
```

回读 A 槽：

```sh
dd if="$APPSBL_A" \
   bs=1 count="$FILE_SIZE" \
   2>/dev/null | md5sum
```

回读 B 槽：

```sh
dd if="$APPSBL_B" \
   bs=1 count="$FILE_SIZE" \
   2>/dev/null | md5sum
```

三次输出必须完全一致：

```text
2266697f5106c170a91e283adf7a3d19
```

如果某个槽不一致：

- 不要重启；
- 只重新写入不一致的槽；
- `sync`；
- 再次回读校验。

两个槽都校验一致后执行：

```sh
sync
```

等待几秒，再进入下一步。

# 十四、进入 U-Boot Web 刷机界面

## 14.1 关闭设备

拔掉亚瑟电源。

暂时拔掉其他网线，只保留电脑与亚瑟 LAN 口的网线。

## 14.2 设置电脑静态IP

Windows以太网 IPv4设置：

```text
IP地址：192.168.1.10
子网掩码：255.255.255.0
默认网关：192.168.1.1
DNS：留空
```

## 14.3 进入恢复模式

1. 路由器断电；
2. 按住背面的 RESET 键；
3. 保持按住 RESET；
4. 插入电源；
5. 继续按住至少10秒；
6. 等待指示灯变为稳定状态后松开。

部分 U-Boot 版本可能需要按住更长时间。社区实测通常是在指示灯稳定蓝色后再松开。

## 14.4 打开 U-Boot 页面

浏览器使用隐私/无痕模式访问：

```text
http://192.168.1.1
```

能看到刷机页面，说明 U-Boot 已经成功运行。

如果打不开：

```powershell
ping 192.168.1.1
```

并检查：

- 网线是否连接 LAN 口；
- 电脑是否为 `192.168.1.10`；
- 子网掩码是否为 `255.255.255.0`；
- 是否关闭了 Wi-Fi；
- 是否使用浏览器无痕窗口；
- 是否确实按住 RESET 后通电。

# 十六、在 U-Boot 中刷入 iStoreOS

在 U-Boot 页面中：

1. 找到固件上传位置；
2. 选择 `squashfs-factory.bin`；
3. 不要选择 `sysupgrade` 文件；
4. 不要上传 GPT 文件；
5. 不要选择“Whole flash/全盘镜像”；
6. 点击上传或更新固件；
7. 等待写入完成。

刷写期间：

- 不要关闭浏览器；
- 不要拔网线；
- 不要断电；
- 不要按 RESET；
- 即使页面进度条长时间不变化，也不要立即断电；
- 至少等待指示灯完成变化并稳定。

第一次刷入必须使用 Factory 镜像；Sysupgrade 镜像用于系统已经运行后的升级。

4. 查看无线是否正常；
5. 查看存储和分区；
6. 暂时不要立即安装大量插件；
7. 暂时不要立即升级到其他固件。

SSH登录后检查：

```sh
uname -a
df -h
lsblk
blkid
ip addr
```

检查无线校准分区是否正常读取：

```sh
ls -l /dev/mmcblk0p15
```

检查 MAC 地址：

```sh
ip link
```

并与原厂后台记录的 MAC 地址进行比较。

# 十八、刷机成功判定

同时满足以下条件，才算刷机成功：

- U-Boot网页可以正常进入；
- iStoreOS可以正常启动；
- 浏览器可以打开 `192.168.1.1`；
- LAN口正常；
- WAN口可以获取地址；
- 2.4GHz无线正常；
- 5GHz无线正常；
- 重启一次后仍能进入系统；
- 原厂备份已保存到电脑；
- `mmcblk0p15.bin` 的备份存在且非0字节。

# 十九、暂时不要执行的操作

第一次成功启动后，不建议立即执行以下操作：

## 19.1 不要直接刷 R24.05.19

KoolCenter目录中同时存在：

```text
iStoreOS-R24.05.19-...-factory
iStoreOS-R24.05.19-...-sysupgrade
```

但较新的大固件可能需要修改分区表，不能因为文件名包含 Factory 就直接假设适配原厂60MB分区。

## 19.2 不要随意刷 GPT

修改 GPT 会改变 rootfs、HLOS和storage等分区布局。

如果 GPT 与固件不匹配，可能出现：

- 系统无法启动；
- rootfs找不到；
- storage分区消失；
- 原厂恢复困难；
- 分区重叠导致数据损坏。

## 19.3 不要格式化 p27

p27通常是大容量 storage 分区。

如果备份还存放在 p27，执行下面命令会直接删除备份：

```sh
mkfs.ext4 -F /dev/mmcblk0p27
```

必须先将所有备份复制到电脑并校验后，才能考虑格式化。

## 19.4 不要混刷不同机型文件

明确禁止：

```text
RE-CS-02固件或U-Boot
RE-CS-07固件或U-Boot
NOR版U-Boot
不明来源的全盘镜像
别人的ART分区
```

# 二十、常见问题处理

## 20.1 F12脚本提示没有sessionid

处理方式：

1. 刷新原厂后台；
2. 重新登录；
3. 确认地址仍为 `192.168.68.1`；
4. 登录成功后再打开控制台；
5. 不要在登录页面执行脚本。

## 20.2 Telnet端口不通

重新运行：

```powershell
Test-NetConnection 192.168.68.1 -Port 23
```

仍失败时：

- 重启浏览器；
- 重新登录后台；
- 重新运行脚本；
- 检查控制台是否出现HTTP错误；
- 检查电脑是否连接了错误网口。

不要因为 Telnet 失败就直接刷官方降级包。

## 20.3 Telnet密码错误

使用：

```text
用户名：root
密码：当前Web后台管理密码
```

如果后台密码包含非常特殊的字符，可以先在原厂后台修改为较简单但足够安全的临时密码，再重新开启 Telnet。

## 20.4 U-Boot文件MD5不一致

立即删除：

```sh
rm -f /tmp/uboot-ipq60xx-emmc-jdcloud_re-ss-01.bin
```

重新传输。

任何情况下都不能跳过 MD5 校验。

## 20.5 写入后回读MD5不一致

不要重启。

重新写入对应槽位：

```sh
dd if="$UBOOT" of="$APPSBL_A" bs=128K
sync
```

或者：

```sh
dd if="$UBOOT" of="$APPSBL_B" bs=128K
sync
```

然后重新回读校验。

## 20.6 U-Boot页面打不开

依次检查：

```text
电脑IP：192.168.1.10
掩码：255.255.255.0
连接口：LAN
访问地址：http://192.168.1.1
浏览器：无痕模式
进入方式：按住RESET再通电
```

## 20.7 刷完固件后打不开后台

先等待更长时间，然后：

```powershell
ipconfig /release
ipconfig /renew
ping 192.168.1.1
```

确认电脑恢复自动获取地址。

## 20.8 设备完全不启动

如果：

- 没有指示灯；
- LAN口不亮；
- U-Boot页面打不开；
- 静态IP也无法 Ping 通；

则可能需要拆机走高通9008恢复。此时需要使用提前备份的：

```text
mmcblk0p13.bin
mmcblk0p14.bin
gpt_primary.bin
ax1800_first_1111m.img
```

9008是该设备的最终救砖手段，但不属于本免拆教程的正常流程。

# 二十一、建议的实际执行顺序

为了最大限度降低风险，建议分成两次完成。

## 第一次操作

只完成：

```text
开启Telnet
→ 检查分区
→ 完整备份
→ 下载备份到电脑
→ 验证备份
```

然后正常关机。

## 第二次操作

确认备份无误后，再完成：

```text
开启Telnet
→ 传输U-Boot
→ 校验U-Boot
→ 写入p13/p14
→ 回读校验
→ 进入U-Boot
→ 刷默认分区版iStoreOS
```

不要在疲劳、网络不稳定或电源不可靠的情况下连续操作。

# 二十二、最终结论

对于京东云亚瑟 AX1800 Pro R4546，当前推荐的免拆流程是：

```text
R4546后台漏洞开启Telnet
        ↓
完整备份原厂关键分区
        ↓
刷jdcloud_re-ss-01专用U-Boot
        ↓
回读校验A/B两个U-Boot槽位
        ↓
进入192.168.1.1 U-Boot页面
        ↓
首刷默认分区版iStoreOS Factory
```

第一次刷机不修改 GPT、不扩容、不直接上大体积新版固件，是风险相对较低的方案。

等默认分区版 iStoreOS 稳定运行、备份确认可用后，再单独进行：

```text
GPT大分区调整
→ 新版iStoreOS/OpenWrt
→ p27作为overlay或存储
→ 安装OpenClash
→ 配置机场与SOCKS5链式代理
```
